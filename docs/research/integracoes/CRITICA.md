## 3. Tralha que entrou (cortar ou adiar)

1. **Botões "Comentar" e "Mover status" na UI (fase 1b)**: a própria recomendação diz que o agente faz o write-back mais barato. Duas superfícies de escrita = dobro de teste e risco. **Cortar** até haver pedido.
2. **Polling em segundo plano a cada 5–10 min + ntfy de "issue nova atribuída"**: GitHub, Jira e Linear já notificam por e-mail e app. É duplicação e consome rate limit (Jira tem limite por custo). Fazer polling **só com a tela aberta**, e em segundo plano só se `source:` existir numa rotina.
3. **"Estimativa de tokens do conjunto" no painel**: irrelevante com tool search ligado (item 8). Mostrar só o nº de tools e o status.
4. **Playwright e Chrome DevTools MCP como "essenciais"**: o Turno já passa `--chrome` (integração Chrome nativa do Claude). Escolher **um** caminho; o preset DevTools MCP serve só para CLIs sem `--chrome`. Rebaixar para "depois".
5. **Injeção no OpenCode (fase 4)**: nenhuma dor ou pedido do usuário cita o OpenCode. Cortar.
6. **Linear na fase 1b com prioridade acima do ADO**, sem critério explícito (item 3). Ou vira "sob demanda", como o ADO, ou os dois sobem juntos.
7. **Backup dos .jsonl / "resume de qualquer diretório" (dor 8)**: o resume já é nativo e a evidência de perda é de 10 reações. Cortar; no máximo um aviso quando `cleanupPeriodDays` for baixo.
8. **Lista longa de presets "depois"** (Supabase, Vercel, Cloudflare, Neon, Figma, PostHog, Kubernetes): o "customizado" já cobre. Manter só os nomes como exemplo na doc, sem preset.

## 4. Dores reais que ficaram de fora

1. **O fabricante absorvendo as features do Turno.** O Claude Code tem agent view (status needs-input, notificações, `claude agents --json`), sessões em background que sobrevivem ao fechar o terminal, `/loop`, tarefas agendadas no Desktop e Remote Control com push. O Codex app tem Automations; Orca, Cursor e Superset também têm agendador. A recomendação cita "ferramentas que envelhecem" (dor 12), mas não tira a consequência: **cada feature do plano precisa de um teste "o Claude ou o Codex já fazem isso nativamente?"**. O que resiste: multi-CLI e multi-conta (agent-pool), Windows de primeira classe, ntfy, e rotinas locais com precheck e keep-awake.
2. **Chamadas internas do próprio Turno herdando MCP e hooks do usuário** (`ai.ts`, item 16). É uma dor de custo e segurança causada pelo próprio Turno. A correção é pequena.
3. **Conflito com os hooks do usuário ao injetar `--settings`**: `--settings` sobrescreve as chaves que passa. Se o Turno injetar `hooks` para status, pode **substituir** os hooks do usuário naquela sessão [U, conferir se `hooks` é mesclado ou substituído]. O Orca evita o caso nas runs internas. Mais um motivo para preferir `claude agents --json` (item 6).
4. **Bitbucket PR review**: o Orca tem cliente nativo de PRs do Bitbucket com cofre de credenciais (`src/main/bitbucket/*`, 14 arquivos). Se o usuário usa Bitbucket, a dor real é provavelmente **revisar e criar PRs** (dor 3), não ter o agente chamando MCP. Perguntar antes (a pergunta 3 da recomendação já pede Cloud vs DC; acrescentar "o que você faz no Bitbucket?").
5. **Rate limit e cota das próprias APIs dos rastreadores**: Jira (custo por pontos), GitLab MCP 60/min no Free, ClickUp Free 100/dia. Isso só aparece na seção "por que não MCP" e não no desenho de polling e cache.
6. **Privacidade do conteúdo do ticket**: issue privada de cliente vai para o provedor do modelo e, no pool, para outra conta. Faltou no `task.md` um aviso ou bloqueio para fontes marcadas como sensíveis. Barato.

## 5. Veredito geral

A espinha da recomendação se sustenta: tela de tasks só para GitHub e Jira com um tipo único; hub de MCP como lançador local injetado por run com `--strict-mcp-config`; nada de marketplace, gateway ou OAuth próprio; e "não injetar tudo em todo agente". As correções acima não mudam a direção. Elas:
- corrigem números (Notion, Trello, Asana > Linear; arquivos do Orca);
- tiram a promessa falsa de "Bitbucket de graça via OAuth";
- trocam a evidência errada da dor 8 e rebaixam evidências de 0 reações;
- acrescentam um item de fase 0 de custo P (isolar `ai.ts`) e um caminho mais barato para o status por aba (`claude agents --json`);
- corrigem a incoerência do cartão de contexto e do resume.
